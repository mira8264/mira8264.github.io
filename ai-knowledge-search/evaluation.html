AI Knowledge Search Evaluation Checklist

Build a reproducible acceptance process before comparing models or prompt versions.

A successful result is not simply a plausible answer. For ai knowledge search, acceptance means the application can demonstrate that the result satisfies its evidence requirements and avoids answering from a document the requester cannot access.

Use a reference set with meaningful variation

Start with real examples that represent the workload, then add boundary cases with missing, contradictory or irrelevant information. Keep a held-out set separate from the cases used to write the prompt. Do not improve a reported score by removing the examples that exposed a regression.

Reference scenario: An employee asks about equipment reimbursement; retrieve the current policy rather than an old FAQ.

Define the task-specific pass condition

Verify that retrieved text supports each answer sentence. This requirement should be checked against the original source rather than another unsupported model assertion.

Review checklist

  • The input contains an access-controlled question and relevant document excerpts.
  • The proposed result contains a concise answer with citations and uncertainty.
  • Verify that retrieved text supports each answer sentence.
  • The review explicitly checks for answering from a document the requester cannot access.
  • The metric is defined as answers supported by accessible sources with a recorded denominator.
  • Token counts, retries and manual corrections are recorded alongside accepted results.

Measure the cost of an accepted result

Count all attempts used to complete the sampled tasks, including retries that were later rejected. Add any review effort separately from token charges. Report the accepted-result rate alongside request volume so a cheap but unreliable configuration is not mistaken for an operational improvement.

Use the token budget calculator to compare illustrative usage profiles. Its output is a planning estimate, not a bill or a measurement of your production traffic.

Decide what blocks a release

Treat a confirmed instance of answering from a document the requester cannot access as a reason to investigate before expanding traffic. Preserve the input, proposed output and review decision. Update the task boundary or validation layer first, then rerun the same reference cases. Do not silently rewrite the evaluation criteria after seeing the result.
