WSL运行Claude Code时项目放哪里

用发行版、项目路径和构建工具位置解决本篇问题：明确项目由哪一侧管理，避免把同一依赖目录在两侧共用。重点防止Windows与WSL同时写同一份临时构建产物，输出应能回到原始输入核对。

Mira 指南编辑组资料核对：2026-10-23返回专题中心

操作步骤

  1. 01

    准备发行版、项目路径和构建工具位置；记录当前WSL发行版、仓库位置与构建工具所在侧，区分Windows路径和Linux路径。

  2. 02

    约定项目由哪一侧管理依赖与构建产物，避免两个系统同时写同一个临时输出目录。

  3. 03

    用同一侧终端运行最小构建和文件读写检查，发现权限或路径异常先排除跨环境引用。

  4. 04

    仓库、工具和构建产物的管理边界明确，路径权限正常，不存在双侧并发写入导致的冲突。

怎样判断已完成

仓库、工具和构建产物的管理边界明确，路径权限正常，不存在双侧并发写入导致的冲突。

容易忽略的地方

Windows与WSL同时写同一份临时构建产物。

示例与记录方式

示例仓库：团队约定由WSL维护依赖与构建产物，Windows侧仅查看需要的资料。接入编辑器时再次确认工具执行侧，不同时开启另一套构建覆盖共享临时目录；验收保留实际路径记录。
