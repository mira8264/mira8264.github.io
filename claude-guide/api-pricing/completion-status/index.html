对API费用进行核对时为什么要保存结束状态

结束状态能够说明结果是否完整及重试必要性，保留请求标识与用量有助于费用核查，不应删除失败样本。

Mira 指南编辑组资料核对：2026-10-23返回专题中心

操作步骤

  1. 01

    记录响应的结束原因、任务是否完成和结果是否通过业务校验。

  2. 02

    把正常完成、输出截断、工具交接和错误等情况分开统计。

  3. 03

    对比费用时同时查看成功交付数量，明确哪些请求需要后续人工或继续调用。

  4. 04

    把结束状态、文本完整性与后续动作对应保存；无法解释的状态查当前官方文档，再决定是否继续生成。

怎样判断已完成

结束状态能解释不完整结果与重试。

容易忽略的地方

HTTP请求成功不等于业务交付已完成，只按状态码计数会夸大有效产出。

示例与记录方式

示例记录：返回文本未完成，同时保存结束原因和请求标识。负责人据此决定继续或调整输入，费用对账时保留原请求，不删除失败样本。
