Claude Code工具输出很长时如何控制成本

工具日志过长时可先筛选错误附近内容并保留原始日志，减少重复传入，同时保证定位问题所需上下文完整。

Mira 指南编辑组资料核对：2026-10-23返回专题中心

操作步骤

  1. 01

    定位会产生大量日志、完整文件或重复列表的操作，明确真正需要检查的范围。

  2. 02

    让任务先读取相关片段和必要错误信息，再按证据扩展到更多文件。

  3. 03

    记录缩小输出后是否仍能定位问题，并保留原始日志在自己的受控位置。

  4. 04

    用筛选后的段落检查是否足够解释故障，不足再补相关位置；原日志留在受控位置，不反复全量发送。

怎样判断已完成

工具输出按任务需要筛选与保留。

容易忽略的地方

不能为了节省用量删去关键错误；只隐藏失败结果可能导致模型继续沿错误方向执行。

示例与记录方式

示例日志处理：构建输出很长，先提取错误附近段落供分析，完整日志在本地保留。避免每轮把相同全量日志重复送入，也不删掉定位所需上下文。
