远程开发中断后如何交接上下文

开发中断的可用交接是一份状态记录：来源提交、执行命令、失败检查与未决授权，让接手人不必猜聊天进展。

Mira 指南编辑组资料核对：2026-10-23返回专题中心

操作步骤

  1. 01

    记录目标分支当前提交和未完成项，未提交修改应注明文件和保留方式。

  2. 02

    附上已运行的命令与结果，失败命令的错误也属于有效交接信息。

  3. 03

    说明授权和未决问题的边界，不让接手者猜测是否允许外部写入。

  4. 04

    接手人先确认状态再继续，先核对主机与提交再执行后续操作。

怎样判断已完成

下一位不需要猜测之前做到了哪里。

容易忽略的地方

不要把长聊天记录当成可执行交接清单；提供包含代码状态和验证结果的记录。

示例与记录方式

示例HANDOFF.md记录源提交、未提交修改、已跑测试、失败样例和下一步。接手者先看实际Git状态，不直接把上一位助手的总结当作当前事实。
