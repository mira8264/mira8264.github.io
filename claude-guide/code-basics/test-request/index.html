Claude Code怎样提出测试要求

用功能契约、边界条件和已有测试框架解决本篇问题：明确期望结果来源，要求覆盖正常、边界及失败情况。重点防止生成与实现采用相同错误假设的测试，输出应能回到原始输入核对。

Mira 指南编辑组资料核对：2026-10-23返回专题中心

操作步骤

  1. 01

    准备功能契约、边界条件和已有测试框架；从外部契约或已知业务例子写出预期结果，避免照搬当前实现作为标准。

  2. 02

    明确期望结果来源，要求覆盖正常、边界及失败情况；要求覆盖正常、边界与失败三类输入，沿用仓库已有测试框架与命令。

  3. 03

    临时制造一个可控错误验证测试会失败，再恢复实现，确认测试真正约束目标行为。

  4. 04

    验收测试能在故意引入错误时失败：测试能识别被故意破坏的功能，且预期结果来自独立需求而非实现的错误假设。

容易忽略的地方

示例与记录方式

示例测试：要求验证折扣门槛前、恰好门槛和超过门槛三种数量，期望结果先由业务规则手工写出。 约定空输入返回空文件而非异常，测试先在旧实现失败，修复后通过，并检查正常输入不退步。
