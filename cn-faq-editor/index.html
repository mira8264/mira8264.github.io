先把任务说清楚

准备资料 → 约定结果 → 检查输出

01 / 输入

准备哪些资料

咨询记录、现行规则、产品说明、问题频次。把已确认事实与仍需补充的信息分开，保留原始资料供后续核对。

02 / 交付

应该得到什么

问题分组、简明回答、依据链接、复查日期。先约定最终交付形式，再决定使用哪个工具，避免生成完才发现不能直接使用。

03 / 约束

这一步尤其重要

区分取消、退款、删除等不同操作，不把相似词当成同一政策。

任务示例

把要求放进具体情境

客户反复询问云服务器是否包含网站迁移，把是否提供、服务范围和需准备资料分别说明。

常见失误

沿用已经改变的服务政策。将这一问题放进样例检查中，比只要求结果更专业更容易执行。

验收重点

问题被直接回答的比例

  • 对照原始资料检查重要事实和限制。
  • 检查交付中是否包含：问题分组、简明回答、依据链接、复查日期。
  • 确认规则已满足：区分取消、退款、删除等不同操作，不把相似词当成同一政策。
  • 记录失败样例，便于下一次对比改进。

比较维度本任务的检查方式
资料支持能否处理你准备的咨询记录，并保留必要格式和来源。
结果可用是否完整包含问题分组，且能继续人工编辑。

常见问题

开始前最少需要准备什么？

至少准备咨询记录，再补充现行规则、产品说明、问题频次。资料缺失时先把问题列出来，不让工具代替你虚构事实。

怎样判断结果是否合格？

重点看问题被直接回答的比例，并检查是否出现沿用已经改变的服务政策。先拿一份可以人工核对的小样本试用，再扩大任务量。

需要一次接入所有工具吗？

不需要。先确认任务需要哪些环节，再选择生成、编辑、校验或部署工具。功能、费用和授权条件请以各产品官方页面为准。
